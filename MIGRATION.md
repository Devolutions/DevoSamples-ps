# Migration: legacy paths → `src/`

This document tracks the relocation campaign that moves every legacy script into the modern `src/` root with full front matter.

## The rule

Status is **location-based**, not toggled per folder:

- Files under `src/**` → strict (front matter required, version gate enforced, lint errors fail).
- Files at legacy repo-root paths (`DVLS/`, `RDM/`, `Hub/`, `custom_batch_actions/`) → lenient forever (warnings only, no front matter required).

The legacy file is **left in place** when its `src/` counterpart is created. Downstream consumers pinned to old paths keep working. A follow-up cleanup PR may delete the legacy file once stakeholders confirm no consumer remains.

## Migration order

One PR per source folder, smallest first:

1. `Hub/Security/` → `src/Hub/security/` (case-normalized)
2. `DVLS/security/` → `src/DVLS/security/`
3. `DVLS/entries/` → `src/DVLS/entries/`
4. `RDM/security/` → `src/RDM/security/`
5. `RDM/datasource/` → `src/RDM/datasource/`
6. `RDM/export/` → `src/RDM/export/`
7. `RDM/import/` → `src/RDM/import/`
8. `RDM/entries/` → `src/RDM/entries/`
9. `custom_batch_actions/` → `src/custom_batch_actions/`

## Per-file migration steps

1. `/migrate <legacy-path>` — copies the file to `src/<same-path>`, runs AST inference to fill front matter, leaves the legacy file untouched.
2. Human reviews the inferred fields (especially `cmdlets`, `params`, `category`).
3. `/lint src/<folder>` — resolve any analyzer warnings on the new file.
4. `/build-catalog -UpdateMigrationDoc` — refreshes the `migrated` column in the table below. Other columns are preserved.
5. Commit + push + open PR titled `Migrate <folder> to src/ with v1 front matter`.

## Migration table

The table below is the canonical to-do list. **Curate `intent`, `priority`, and `notes` by hand.** `migrated` is regenerated by `tools/Build-Catalog.ps1 -UpdateMigrationDoc` based on whether `target_src_path` exists with `status: active` — don't edit that column manually.

Column meanings:

- **intent**: `todo` (migrate it) | `deprecated` (don't migrate; stays legacy forever and may be deleted in a future stakeholder-confirmed cleanup) | `done` (auto-derived; do not set by hand — set by `/build-catalog` flipping `migrated`).
- **priority**: `high` | `medium` | `low`. Drives Phase 2 sequencing within a folder.
- **migrated**: ☐ pending / ☑ live under `src/`. Auto-flipped.
- **notes**: free text — context, owners, links, downstream consumers, anything worth remembering.

## Sunsetting

Once every `intent: todo` row is ☑, a per-folder deletion PR may remove the legacy files. Each deletion is gated by stakeholder confirmation — there is no automatic cutoff date.

Scripts classified `intent: deprecated` are not migrated. They remain at the legacy path indefinitely (so existing consumers keep working) and are also candidates for the eventual stakeholder-gated deletion.
